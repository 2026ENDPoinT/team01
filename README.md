# team01 — 성적 관리 프로그램

ENDPoinT 해커톤 2026 Team 01 (구현과제 트랙)

C++17 프로그램이 로컬 HTTP 서버로 동작하고, 브라우저에서 `http://localhost:8080` 으로 접속해서 사용합니다.

## 문제 정의

- 대상: 학과 사무실·교수·학생이 같은 성적 데이터를 서로 다른 엑셀·메신저로 따로 관리하는 소규모 학과
- 문제: 성적 입력, GPA(4.5 만점) 계산, 재수강·학사경고 판정, 석차, 수강신청 정원·시간표 겹침 확인이 사람마다 다른 기준으로 수작업되어 오류가 납니다.
- 해결: 하나의 로컬 서버에서 역할(관리자·교수·학생)별 권한으로 입력하고, GPA·석차·학사경고·재수강을 자동 계산해 같은 기준으로 보여 줍니다. 설치 없이 브라우저로 접속하고 데이터는 CSV 파일로 남습니다.
- 시연: 아래 "필수 기능 대응표"(심사 필수 ①~⑤ → 화면 위치·API)와 "시연 시나리오"(클릭 경로와 기대 결과)를 순서대로 따라가면 됩니다.

## 빌드 / 실행

필요: CMake 3.16+, C++17 컴파일러 (GCC, Clang, MSVC, MinGW)

**CLion**: 폴더 열기 → `GradeManager` 실행 → 브라우저에서 http://localhost:8080

**명령줄**
```bash
cmake -B build
cmake --build build
./build/GradeManager          # Windows: build\Debug\GradeManager.exe
./build/GradeManager 9090     # 8080 이 이미 사용 중이면 다른 포트로
```

`data/`, `web/` 경로는 빌드 시 프로젝트 경로로 고정되므로 어디서 실행해도 됩니다.

**테스트**
```bash
cmake -B build && cmake --build build && ctest --test-dir build --output-on-failure
# Windows(Visual Studio): ctest --test-dir build -C Debug --output-on-failure
# CMake 3.20 미만 (--test-dir 없음): cd build && ctest --output-on-failure
```

`tests/` 는 외부 라이브러리 없이 `GradeTests` 하나로 등급 경계·등급 직접 입력 변환, 재수강 규칙, 석차 동점, 평가 기준 최종 점수·성적 자동 계산, 상대평가 등급 배정, 학기별 GPA 요약, 과목코드 변경·삭제 연쇄, CSV 저장/불러오기를 검사합니다 (임시 폴더만 사용, `data/` 는 건드리지 않음).

## 학기 규칙

- 학기 형식: `YYYY-N` (예: `2026-1`), N 은 1~4 — 1·2 는 정규학기, 3 은 여름 계절학기, 4 는 겨울 계절학기 (#20)
- 학생별 허용 학기: 입학년도(2000 + 학번 앞 2자리)-1 ~ (올해+1)-4 (#16). 예: `23101001` 은 2023-1 ~ 2027-4 (2026년 기준). 범위 밖이면 성적·수강신청 등록이 `400`. 이미 저장된 데이터는 다시 검사하지 않습니다.

## 로그인 / 역할

계정은 관리자가 만듭니다 (학생을 등록해도 계정이 자동으로 생기지 않음). 관리자 계정이 하나도 없는 상태로 시작하면 (첫 실행 등) `admin` / `admin1234` (학교 관리자) 가 자동으로 만들어지고 콘솔에 안내가 나옵니다. 로그인한 뒤 비밀번호를 바꾸세요.

- 아이디: 영문·숫자·`_` 3~20자 (바꿀 수 없음), 비밀번호: 8~64자 (salt + SHA-256 반복 해시로 저장)

## 수강신청

- 신청 학기는 관리자가 설정합니다 (`settings.csv`). 비어 있으면 수강신청 기간이 아닙니다. 학생은 신청 학기에만 신청·취소할 수 있고, 관리자는 어느 학기든 대리로 신청·취소할 수 있습니다.
- 신청 검사: 중복 (`409`), 정원 (그 학기 신청 인원이 정원 이상이면 `409`), 같은 학생·학기에 신청한 과목과 강의시간 겹침 (`409`). 강의시간이 빈 과목(원격 등)은 겹치지 않습니다.
- 성적 등록은 같은 (학번, 과목, 학기)의 수강신청이 있어야 합니다 (없으면 `409`). 성적 또는 평가 항목 점수가 있는 수강은 취소할 수 없습니다 (`409`). 출석부 계산값(`출석`)은 항목 점수로 세지 않습니다.
- 과목 목록의 수강 표시 (#14): 수강신청이 있는 가장 늦은 학기의 신청 인원 / 학기당 정원 (`GET /api/stats/course/:code` 의 `latestSemester`, `latestEnrolled`)

## 과목 페이지

- 상단 탭 줄에 보이는 과목마다 탭이 하나씩 생깁니다. 보이는 과목은 관리자는 전체, 교수는 담당 과목, 학생은 수강신청한 과목입니다. 수강과목 목록도 같은 과목만 보여 줍니다.
- 과목 페이지는 학기별로 나뉘고, 게시물은 주차(1~16)별로 묶어 보여 줍니다. 분류는 수업자료 `material` · 중간고사 `midterm` · 기말고사 `final` · 과제 `assignment` 4가지입니다.
- 게시물은 제목(필수), 내용, 링크(`http://` 또는 `https://`, 파일 업로드는 없음), 날짜(과제 마감·시험일, `2026-10-20` 또는 `2026-10-20 13:00`)를 가집니다. 작성자와 작성 시각은 서버가 채웁니다.
- 관리자·담당 교수에게는 게시물 아래에 `평가 기준` 영역과 `출결` 영역이 보입니다 (아래 "평가 기준과 성적 계산", "출결" 참고).

| 기능 | 관리자 | 교수 | 학생 |
|---|---|---|---|
| 게시물 조회 | 모든 과목 | 담당 과목 | 수강신청한 과목 (그 수강신청 학기의 게시물만) |
| 게시물 추가·수정·삭제 | O | 담당 과목 | X |

## 평가 기준과 성적 계산

교수가 과목·학기마다 평가 기준(분류 6개의 반영 비율과 등급 방식)을 정하고 학생별 항목 점수를 넣으면, 최종 점수와 등급이 자동으로 계산되어 `grades.csv` 의 성적이 됩니다. 계산 결과는 평범한 성적이라서 GPA·석차·재수강·학사경고·성적표 코드는 그대로 씁니다 (`include/assessment.h`, `GradeManager` 의 `syncGrade`·`syncCourse`).

- 분류 6개: `출석` `중간고사` `기말고사` `과제` `팀프로젝트` `기타` (`assessmentCategories()`, 화면·API·CSV 모두 이 순서·이 글자). 평가 기준을 저장하면 6개를 모두 저장하고, 새 분류를 만들거나 이름을 바꿀 수는 없습니다.
- 비율은 분류마다 0~100 정수입니다. 0% 는 그 과목·학기에 반영하지 않는다는 뜻이고, 6개의 합계는 100 이어야 저장됩니다. 평가 기준은 한 번에 설정하며 (분류별 추가·수정·삭제는 없음). 처음 만들 때와 바꿀 때 같은 라우트를 씁니다.
- 최종 점수 = Σ(항목 점수 × 비율) ÷ 100, 소수 둘째 자리에서 반올림 (`finalScore`). 비율 0 인 분류는 무시합니다. 예: 비율 출석 10·중간 30·기말 40·과제 20·팀 0·기타 0 에 점수 100·90·80·100 → 10 + 27 + 32 + 20 = 89.0 → B+.
- 미완성이면 성적이 없습니다. 비율 합계가 100 이 아니거나 비율이 0 보다 큰 분류에 점수가 없으면 그 학생의 성적은 만들어지지 않고, 이미 있던 성적도 지워집니다 (항목 점수를 지운 경우).
- 평가 기준이나 항목 점수를 바꿀 때마다 서버가 성적을 다시 계산합니다. 평가 기준을 바꾸면 그 과목·학기 수강생 전원, 항목 점수를 바꾸면 그 학생만 대상입니다.
  - 비율을 0 으로 바꾼 분류의 항목 점수는 지워집니다.
  - 평가 기준을 삭제하면 항목 점수·등급 방식·그 과목·학기 성적이 모두 지워지고, 직접 입력 과목으로 돌아갑니다.
  - 과목코드를 바꾸면 평가 기준·항목 점수·등급 방식의 코드도 바뀌고, 과목이나 학생을 삭제하면 같이 지워집니다.
- 항목 점수는 0~100 이고, 그 학생의 (과목, 학기) 수강신청이 있어야 입력할 수 있습니다. 비율이 0% 인 분류에는 점수를 입력할 수 없습니다.
- 출석은 출석부에서 자동으로 계산합니다. `출석` 비율이 0 이 아니면 항상 그렇고, 교수가 직접 입력할 수 없습니다.
  - 항목 점수로 저장하지 않고 그때그때 계산합니다: 그 학생의 출결 기록이 있으면 출결 점수 ("출결" 참고), 기록이 하나도 없으면 100점입니다.
  - 출결을 기록·수정·삭제하면 그 학생의 성적이 다시 계산됩니다. 점수 입력표에서 `출석` 칸은 항상 잠겨 있습니다.
- 직접 입력한 성적과 섞이지 않습니다.
  - 그 과목·학기에 직접 입력한 성적이 이미 있으면 평가 기준을 처음 만들 수 없습니다 (`409`).
  - 평가 기준이 있는 과목·학기는 성적 직접 등록·수정·삭제가 모두 `409` 입니다.
  - 성적 또는 항목 점수가 있는 수강은 취소할 수 없습니다 (`409`). `출석` 계산값만 있는 수강은 취소할 수 있습니다. 수강신청 목록의 `hasGrade` 는 성적 또는 항목 점수가 있으면 `true` 입니다.
- 평가 기준이 없는 과목·학기는 지금처럼 점수 또는 등급(`A+ A0 B+ B0 C+ C0 D+ D0 F` → 95·90·85·80·75·70·65·60·0점으로 저장)으로 직접 입력하고, 등급은 절대평가(점수 기준)입니다.

**등급 방식**: 평가 기준과 함께 과목·학기마다 `absolute`(절대평가) 또는 `relative`(상대평가)를 고르고 `grading_modes.csv` 에 저장합니다.
- 절대평가: 점수 기준 등급입니다 (95 이상 A+, 90 이상 A0, … `scoreToLetter`).
- 상대평가: 그 과목·학기 최종 성적들의 등급을 순위에 따라 다시 정합니다 (`include/relative_grading.h`, `RelativeGrading::assignLetters`). 규칙은 **A0 이상 30% 이하, B0 이상 70% 이하, 평균 평점 3.50 이하** 입니다.
  - 상한 인원은 문구 그대로 내림입니다: n 명이면 A0 이상 ⌊n × 0.30⌋ 명, B0 이상 ⌊n × 0.70⌋ 명 (10명이면 3명·7명, 2명이면 0명·1명, 1명이면 0명·0명). n 은 그 과목·학기에 최종 성적이 있는 학생 수입니다.
  - 알고리즘: ① 점수 기준 등급에서 시작하고 등급을 내리기만 합니다. ② 점수가 높은 순으로, 같은 점수끼리 한 묶음으로 처리합니다. A 등급 묶음이 A0 이상 상한을 넘으면 묶음 전체를 B+ 로, B 등급 묶음이 B0 이상 상한을 넘으면 묶음 전체를 C+ 로 한 칸씩 내립니다. 한 번 닫힌 상한은 더 낮은 점수에게 다시 열리지 않아서, 점수가 높은 학생이 더 낮은 등급을 받는 일이 없고 동점자는 함께 올라가거나 함께 내려갑니다. ③ 그래도 평점 평균이 3.50 을 넘으면 가장 높은 등급 중 점수가 가장 낮은 묶음을 한 단계 내립니다 (안전장치).
  - 정해진 등급은 `grades.csv` 의 `letter` 칸에 저장하고 (`Grade::letter()`), GPA·석차·성적표·CSV·학사경고가 모두 이 등급을 씁니다. 재수강 성적의 A0 제한은 그 뒤에 적용합니다. 성적이 생기거나 바뀌거나 지워질 때, 등급 방식이 바뀔 때마다 그 과목·학기 등급을 다시 정합니다. 절대평가로 되돌리면 `letter` 칸이 비워집니다.
  - 예: 최종 성적이 1명이면 상한이 0명이라 89점도 C+ 입니다. 2명 (89점, 79.35점)이면 B0 이상 상한이 1명이라 B+, C+ 입니다.

**예상 성적** (학생 `내 성적`): 평가 기준이 있는 과목마다 "진행 중 과목 (평가 항목)" 영역에 내 항목 점수와 현재까지 환산을 보입니다. 비율 0 인 분류는 표에서 뺍니다. 화면에서 계산하며 저장하지 않습니다.
- 현재까지 환산 = Σ(입력된 항목 점수 × 비율) ÷ Σ(입력된 항목의 비율). 예상 등급은 `scoreToLetter` 와 같은 경계를 씁니다. 최종 성적이 생기기 전에는 "미확정"이고, 생기면 그 성적을 보입니다.
- 최종 성적이 없는 과목은 점수가 없는 분류(출석 제외)의 `내 점수` 칸에 예상 점수를 넣을 수 있습니다. 입력할 때마다 그 과목 줄을 다시 계산하고, 서버로 보내지 않으며 화면을 다시 그리면 사라집니다.
  - 빈 칸이 남아 있으면 칸을 채운 분류까지 반영해 현재까지 환산을 보이고, 비율이 0 보다 큰 분류가 모두 차면 `예상 최종 NN.NN점` (점수 기준 등급, 미확정) 을 보입니다.
  - 상대평가 과목이면 실제 등급은 수강생 순위로 정해진다는 안내가 붙습니다. 0~100 밖의 입력은 계산에서 빼고 칸에 표시합니다.
  - 예: 윤지아 `25103008` (중간 72·과제 85)가 기말에 80 을 넣으면 출석 기록이 없어 출석 100 이므로 (72×30 + 80×40 + 85×20 + 100×10) ÷ 100 = 80.60 (B0). 출결 기록으로 출석이 87.5 이면 79.35 (C+).

## 출결

교수가 과목 페이지에서 주차별 출결을 기록하면 서버가 학생별 출석 점수를 계산합니다. 그 과목·학기 평가 기준의 `출석` 비율이 0 보다 크면 이 점수가 학생의 `출석` 분류 점수로 성적 계산에 들어가고 (기록이 하나도 없으면 100점), 이후는 "평가 기준과 성적 계산" 과 같아서 최종 성적·GPA 까지 다시 계산됩니다 (`include/attendance.h`, `GradeManager::setAttendance`, `attendanceCategoryScore`).

- 수업은 16주(주차 1~16, 게시물 주차와 같음)입니다. 기록은 (학번, 과목코드, 학기, 주차) 하나에 상태 하나이고, 상태는 `출석` `지각` `결석` `공결` 입니다. 공결은 출석과 같게 봅니다. 그 학생의 (과목, 학기) 수강신청이 있어야 기록할 수 있습니다.
- 지각 3회 = 결석 1회: 결석 환산 = 결석 + 지각 ÷ 3 (나머지는 버림).
- 출석 점수 = 100 × (16 − 결석 환산) ÷ 16, 소수 둘째 자리 반올림, 0 미만이면 0. 기록이 없는 주차는 출석으로 봅니다. 기록이 하나도 없으면 점수가 없습니다 (`score` 가 `null`). 단, 성적 계산의 `출석` 분류 점수는 기록이 하나도 없으면 100 입니다. 예: 결석 1 → 93.75, 지각 3 → 93.75, 결석 2 → 87.5.
- 결석 환산이 5 를 넘으면(16주의 1/3 초과) `출석 미달` 경고만 보입니다. 등급을 자동으로 F 로 바꾸지는 않습니다.
- `출석` 분류 자동 연동: `출석` 비율이 0 보다 큰 (과목, 학기)의 출석 점수는 항목 점수로 저장하지 않고 출결 기록에서만 정해집니다. 출결을 바꿀 때마다 그 학생의 성적을 다시 계산하고, 그 학생의 기록을 모두 지우면 출석 점수는 100 이 됩니다. `출석` 점수를 직접 입력·삭제하면 항상 `409` 입니다. 평가 기준이 없거나 `출석` 비율이 0 인 과목·학기는 기록만 하고 성적에는 반영하지 않습니다.
- 과목코드·학번을 바꾸면 출결 기록도 따라가고, 과목이나 학생을 삭제하면 출결 기록도 지워집니다.

화면:
- 과목 페이지 `출결` 영역 (관리자·담당 교수, `평가 기준` 영역 아래): 자체 학기 선택 (처음에는 평가 기준 영역과 같은 학기), 행 = 그 학기 수강생, 열 = 1~16주. 칸을 누르면 `없음 → 출석 → 지각 → 결석 → 공결 → 없음` 순으로 바뀌고 바로 저장합니다 (`없음` 은 기록 삭제). 저장에 실패하면 칸이 이전 값으로 돌아가고 오류 알림이 뜹니다. 16주 열이 화면보다 넓으면 표 안에서 가로로 스크롤합니다.
- 행 끝에 결석 환산과 출석 점수 (소수 둘째 자리, 기록이 없으면 `-`), 미달이면 `출석 미달` 배지를 보입니다. 저장할 때마다 그 학생의 행 끝 값과, 같은 학기 평가 항목 점수표의 최종 열을 서버 값으로 다시 그립니다. 점수표의 `출석` 칸은 항상 읽기 전용입니다.
- 학생 `내 성적` 의 "진행 중 과목 (평가 항목)" 에 출결 기록이 있는 과목마다 `출석 N · 지각 N · 결석 N · 출석 점수 NN.NN` (미달이면 `출석 미달`) 을 보입니다. 기록이 없는 과목은 보이지 않습니다.
- 화면은 출석 점수를 다시 계산하지 않고 서버가 준 `summaries` 를 그대로 보입니다. 출결을 불러오지 못하면 그 영역 안에 한 줄 오류만 보이고 다른 영역은 그대로 동작합니다.

| 출결 권한 | 관리자 | 교수 | 학생 |
|---|---|---|---|
| 출결 조회 | 과목·학기 전체 | 담당 과목 | 본인 기록 전체 |
| 출결 기록·수정·삭제 | O | 담당 과목 | X |

| 담당 과목이 아닌 교수, 학생이 쓰기 라우트 호출 | `403` | `권한이 없습니다` |

JSON 필드 이름은 헤더의 멤버 이름과 같습니다.
- 학생 `{"id", "name", "major", "year"}`
- 과목 `{"code", "name", "credit", "professor", "category", "area", "schedule", "language", "capacity", "remote"}`
  - `code` 과목코드: 숫자 6자리 (예: `109004`). 수정할 때 바꾸면 그 과목의 성적에 적힌 코드도 같이 바뀜
  - `category` 이수구분: `전공필수` `전공선택` `교양필수` `교양선택` `일반선택`
  - `language` 강의언어: `한국어전용` `영어전용` `모듈강좌(M)`
  - `schedule` 강의시간: `월(1~4)`, `화(2~3) 목(2~3)`, `금(5)` 형식 (빈 값 허용), `area` 교양영역 (빈 값 허용)
  - `capacity` 학기당 정원 (0 = 제한 없음, 최대 999). 정원은 수강신청에서 검사 (그 학기 신청 인원이 정원만큼 있으면 수강신청은 `409`)
  - `remote` 원격강좌 여부 (`true`/`false`)
  - 예전 형식 `courses.csv` (`code,name,credit,professor`) 도 읽고, 다음 저장 때 새 형식으로 바뀜
- 성적 `{"studentId", "courseCode", "semester", "score", "letter"}` — 요청에는 `score` 대신 `letter` 를 보낼 수 있고, 응답의 `letter` 는 서버가 정함 (`Grade::letter()` = 상대평가로 정해진 등급이 있으면 그것, 없으면 `scoreToLetter` 를 거친 뒤 재수강 규칙 `Retake::officialLetter`)
- 수강신청 `{"studentId", "courseCode", "semester", "hasGrade"}` — 같은 (학번, 과목코드, 학기) 하나가 신청 1건
- 게시물 `{"id", "courseCode", "semester", "category", "week", "title", "body", "link", "dueDate", "author", "createdAt"}`
- 계정 `{"username", "role", "name", "studentId"}` — 응답에 비밀번호 해시는 없음. 학생 계정의 `name` 은 학생 이름으로 채워서 내보냄
- 평가 기준 `{"courseCode", "semester", "mode", "items"}` — `mode` 는 `absolute` `relative`, `items` 의 원소는 평가 항목 `{"courseCode", "semester", "name", "weight"}` (`name` 은 분류 6개 중 하나, `weight` 는 반영 비율(%) 정수 0~100)
- 항목 점수 `{"studentId", "courseCode", "semester", "name", "score"}` — `score` 는 0~100
- 출결 `{"studentId", "courseCode", "semester", "week", "status"}` — `week` 는 1~16, `status` 는 `출석` `지각` `결석` `공결`

데이터를 바꾸는 라우트의 성공 응답은 모두 JSON 입니다. 등록은 `201` + 만든 객체, 수정은 `200` + 바뀐 객체, 삭제는 `200` + `{"deleted": true}` 이고, 성공한 뒤 바로 CSV 에 저장합니다. 성적 응답에는 항상 `letter` 가 들어 있습니다.

## 재수강 규칙

같은 학생이 같은 과목을 여러 학기에 들으면 가장 늦은 학기가 재수강 성적이고, 그 전 성적은 삭제된 성적입니다. 자세한 내용과 함수는 `include/retake.h` 를 참고하세요.

- 재수강 성적은 A0 까지만 받습니다 (95점 이상이어도 A0, 평점 4.0).
- 삭제된 성적은 GPA, 석차, 과목 통계, 과목 성적표에서 빠집니다. `grades.csv` 에는 그대로 남습니다.
- 학생 성적표: 2018년 이후 입학생(학번 앞 2자리 ≥ 18)은 삭제된 과목을 등급 `R` 로 표시하고, 그 전 입학생은 그 줄을 뺍니다.
- 학사경고: 이미 내려진 학사경고는 유지합니다. 학사경고를 판단할 때는 재수강 규칙을 적용하지 않고 원래 등급(`Grade::letter`, 상대평가로 정해진 등급이 있으면 그것)을 씁니다 (`statistics.h` 의 `academicWarnings`).
  - 기준: 정규학기 평점평균 1.75 미만, 또는 수강신청 미이행 (그 학기에 신청한 학점이 1 미만)
  - 판단 학기: 그 학생이 처음 수강신청한 학기부터, 전체 성적 데이터에 있는 가장 늦은 정규학기(N=1·2)까지 정규학기마다 봅니다. 계절학기는 판단하지 않습니다. 수강신청 기록이 없는 학생은 판단하지 않고, 휴학 데이터가 없으므로 모두 재학생으로 봅니다.
  - 각 학기: 신청 학점 합계가 1 미만이면 `수강신청 미이행`, 아니고 그 학기 성적이 1건 이상이면 학점 가중 평점(재수강으로 지워진 성적도 포함)이 1.75 미만일 때 `평점평균 1.75 미만`
  - 결과 항목 `{semester, reason, gpa, credits}` (`gpa` 가 없으면 `null`, `credits` = 그 학기 신청 학점). 샘플 데이터에서는 최유진 2025-2·2026-1, 강도윤 2026-1, 윤지아 2025-2, 한지민 2025-1 (평점)·2026-1 (수강신청 미이행)

| ① 과목·성적 등록 (과목명, 수강 학기, 학점, 성적 등급) | 수강과목 탭 `+ 과목 등록` (과목명·학점) → 수강신청 탭 (학생·과목·학기 선택 후 `신청`) → 성적 탭 `+ 성적 등록` 에서 입력 방식 `등급` 선택 (A+ ~ F) | `POST /api/courses`, `POST /api/enrollments`, `POST /api/grades` (`letter`) |
| ② 과목 조회·관리 (학기별 구분, 수정·삭제) | 성적 탭 목록 (학기·학생·과목으로 거르기, 행마다 `수정` `삭제`), 수강과목 탭·과목 탭의 과목 목록·정보 (`수정` `삭제`) | `GET /api/grades?semester=`, `PUT`·`DELETE /api/grades`, `PUT`·`DELETE /api/courses/:code` |
| ③ 평점평균(GPA) 자동 계산 (4.5 만점, 소수 둘째 자리) | 학생 탭 → `성적표` 대화상자: 누적 GPA·등록 학점, 학기별 평점평균·등록 학점 표, GPA 변화 그래프. 학생 계정은 `내 성적` 탭 (같은 화면). 석차 탭의 GPA 도 같은 값 | `GET /api/stats/summary/:id`, `GET /api/stats/gpa/:id`, `GET /api/stats/ranking` |
| ④ 데이터 저장·불러오기 | 모든 등록·수정·삭제가 바로 `data/*.csv` 에 저장됨. 새로고침하거나 서버를 다시 켜고 로그인해도 같은 값 | 데이터를 바꾸는 라우트가 성공 뒤 `gm.save()` |
| ⑤ 기본 예외 처리 | 과목명 빈칸, 학점 0·숫자 아님, 지원하지 않는 등급, 성적 없는 학생 GPA 는 서버가 `400` + 메시지(GPA 는 `null`)로 돌려주고 화면이 오류 문구를 알림으로 보임. 성적 없는 학생(조서준)의 성적표는 "등록된 성적이 없습니다" | `400` 응답 (아래 시연 시나리오의 6번에 실제 문구), `GET /api/stats/gpa/:id` 의 `"gpa": null` |

| 수정 반영: 성적이나 학점을 고치면 GPA 가 다시 계산된다 | 성적 탭 `수정` 후 `성적표`. 평가 항목 점수를 고쳐도 같음 (과목 페이지의 항목 점수 입력표) |

## 시연 시나리오

서버를 `./build/GradeManager` 로 띄우고 http://localhost:8080 에서 따라갑니다. 숫자는 샘플 데이터 기준이고, GPA 는 화면에 소수 둘째 자리까지 나옵니다. 앞부분은 심사 필수 기능 순서(1~6), 뒤는 차별점(7~11)입니다.

**필수 기능 (관리자 `admin` / `admin1234`)**

1. 학기 구분, 과목·성적 등록 (필수 ①)
   1. 수강과목 탭 `+ 과목 등록`: 과목 코드 `109501`, 과목명 `데이터베이스`, 이수구분 전공선택, 학점 3, 담당 교수 `이영희`, 강의시간 `화(3~4)`, 정원 `1` → 저장. 기대: 상단에 `데이터베이스` 탭이 생김.
   2. 수강신청 탭: 학생 김민준, 과목 데이터베이스, 학기 `2026-1` → `신청`.
   3. 성적 탭 `+ 성적 등록`: 김민준, 데이터베이스, 학기 `2026-1`, 입력 방식 `등급` → `A+` → 저장. 기대: 목록에 2026-1 데이터베이스 95점 A+ (등급 대표 점수).
   4. 다른 학기: 수강신청 탭에서 김민준·캡스톤디자인·학기 `2026-2` 신청 → 성적 탭 `+ 성적 등록`, 입력 방식 `점수` 에 `87` → 저장. 기대: B+. 성적 탭 학기 선택으로 2026-1 과 2026-2 가 따로 보임.
2. 추가 반영: 학생 탭에서 김민준 `성적표`. 기대: 학기별 표 2025-1 3.94 / 8학점, 2025-2 4.50 / 3학점, 2026-1 4.00 / 6학점, 2026-2 3.50 / 4학점, 누적 3.95 / 21학점 (추가 전 누적은 3.96 / 14학점). 학기별 GPA 변화 그래프도 4점으로 그려짐.
3. 수정 반영: 성적 탭에서 김민준 캡스톤디자인 2026-2 `수정` → 점수 `92` (A0). 기대: `성적표` 의 2026-2 가 4.00, 누적 4.05. 석차 탭에서 김민준 2위 (4.05, 1위 정하은 4.18).
4. 삭제 반영: 같은 성적을 `삭제`. 기대: 성적표에서 2026-2 줄이 사라지고 누적 4.06 / 17학점.
5. 데이터 유지: 브라우저를 새로고침(F5)해도 같음. 터미널에서 Ctrl+C 로 서버를 끄고 다시 실행해 로그인하면 김민준 성적표가 그대로 (데이터베이스 2026-1 A+, 누적 4.06 / 17학점). `git diff data/` 에도 변경이 보임.
6. 예외 처리 (필수 ⑤). 서버는 모든 경우에 계속 동작합니다.
   - 수강과목 탭 `+ 과목 등록` 에서 과목명을 비움: `400` `과목 정보가 올바르지 않습니다 (과목명이 비어 있습니다)`
   - 학점 `0`: `400` `과목 정보가 올바르지 않습니다 (학점은 1~4 사이여야 합니다)`
   - 학점 `abc` (화면 숫자 칸으로는 못 넣으므로 curl): `400` `과목 정보가 올바르지 않습니다`
   - 성적 등급 `A` (화면 선택 상자에는 없는 값이라 curl): `400` `지원하지 않는 성적 등급입니다 (A+ A0 B+ B0 C+ C0 D+ D0 F)`
   - 성적 없는 학생: 학생 탭에서 조서준 `성적표` → "등록된 성적이 없습니다" (`GET /api/stats/gpa/26101007` → `{"gpa":null}`)

   curl 예 (`admin` 로그인 쿠키를 `jar` 에 저장):
   ```bash
   curl -s -c jar -H 'Content-Type: application/json' -d '{"username":"admin","password":"admin1234"}' localhost:8080/api/login
   curl -s -b jar -H 'Content-Type: application/json' -d '{"code":"109502","name":"운영체제","credit":"abc","professor":"이영희"}' localhost:8080/api/courses
   curl -s -b jar -H 'Content-Type: application/json' -d '{"studentId":"23101001","courseCode":"109501","semester":"2026-1","letter":"A"}' localhost:8080/api/grades
   curl -s -b jar localhost:8080/api/stats/gpa/26101007
   ```

**차별점**

7. 평가 기준·출석 자동·상대평가·예상 성적: 교수 `leeyh` / `prof1234` 로 로그인 (로그아웃 후).
   1. 상단 `자료구조` 탭 → 학기 `2026-2` 선택 → `평가 기준` 영역. 기대: 출석 10·중간고사 30·기말고사 40·과제 20·팀프로젝트 0·기타 0 (0% 줄은 흐리게), `비율 합계 100 / 100`, 방식 `절대평가 (점수 기준)`. 항목 점수 입력표의 열은 출석(잠김)·중간고사·기말고사·과제.
   2. 강도윤 행은 중간 90·과제 100 이고, 출석은 출결 기록이 없어 100 이며, 기말이 비어 있어 최종 `-`. 기말에 `80` 입력. 기대: 최종 89 B+ (출석 100 기준), 성적 탭에 자료구조 2026-2 강도윤 B+ 가 자동으로 생김.
   3. 수정 반영(항목 점수): 기말을 `100` 으로 고침 → 97.0 A+, 다시 `80` → 89.0 B+. 기말 칸을 비우면 최종이 `-` 로 돌아가고 성적이 사라짐 (다시 `80` 입력). 관리자의 강도윤 성적표에서 2026-2 는 3.50 / 3학점, 누적 2.31 → 2.64 (11학점).
   4. 비율 합계 보호: `평가 기준 설정` 에서 합계를 99 로 만들어 저장. 기대: 폼과 알림에 `비율 합계가 100이어야 합니다 (지금 99%)`.
   5. 상대평가: `평가 기준 설정` 에서 방식을 `상대평가` 로 저장. 기대: 최종 성적이 강도윤 1명뿐이라 상한이 0명이 되어 강도윤 `89 C+`, 요약 줄 `A0 이상 0명 / 상한 0 · B0 이상 0명 / 상한 0 · …`.
   6. 학생 `25103008` / `student1234` (윤지아) 로그인 → `내 성적` 탭의 "진행 중 과목 (평가 항목)": 자료구조 2026-2 의 기말고사 `내 점수` 칸에 `80` 입력. 기대: `예상 최종 NN.NN점` 이 나옴. 출석 기록이 없어 출석 100 이면 80.60 (B0), 출결 데모 기록으로 출석이 87.5 이면 79.35 (C+). 상대평가 과목이라는 안내 문구가 붙고, 화면을 다시 그리면 입력이 사라지며 서버에는 저장되지 않음.
   7. 다시 교수로 로그인해 윤지아 기말에 `80` 입력. 기대: 최종 성적이 2명이 되어 B0 이상 상한이 1명이므로 강도윤 `B+`, 윤지아 `C+`.
   8. 직접 입력 차단: 점수 입력표의 `출석` 칸은 비활성이고, API 로 `출석` 항목 점수를 입력하면 `409` `출석 점수는 출석부에서 자동 계산됩니다`, 팀프로젝트(0%)는 `409` `비율이 0%인 항목에는 점수를 입력할 수 없습니다`. 자료구조 2026-2 에 성적을 직접 등록·수정·삭제하면 `409` `평가 항목으로 성적을 계산하는 과목입니다 (평가 항목 화면에서 점수를 입력하세요)`. 기말 등 항목 점수가 있는 수강은 수강신청 탭의 `취소` 버튼이 비활성화되고, API 로 취소하면 `409` `성적이 있는 수강은 취소할 수 없습니다`.
8. 재수강 `R` / A0 제한: 관리자 학생 탭에서 윤지아 `성적표` → 미적분학 2025-2 줄이 등급 `R`(삭제된 성적), 2026-1 재수강 성적이 반영됨. 한지민 `성적표` → 자료구조 2025-2 는 97점이어도 A0 (재수강은 A0 까지), 2025-1 줄은 빠짐 (2017년 입학).
9. 학사경고: 학생 탭의 학사경고 열과 각 `성적표` 의 학사경고 목록. 기대: 최유진 2025-2·2026-1, 강도윤 2026-1, 윤지아 2025-2, 한지민 2025-1 (평점)·2026-1 (수강신청 미이행). 석차 탭에서는 이서연·박지호가 같은 등수.
10. 역할별 권한: 윤지아로 로그인한 상태에서는 수강과목·수강신청·내 성적 탭만 보이고, 남의 GPA (`GET /api/stats/gpa/23101001`) 는 `403` `권한이 없습니다`. 교수 `kimcs` / `prof1234` 는 담당 과목 109001 만 다루고, 109201 의 항목 점수 조회·평가 기준 설정은 `403` `권한이 없습니다`.
11. 수강신청 정원·시간 충돌: 관리자가 이서연으로 데이터베이스 `2026-1` 신청 → `409` `2026-1 데이터베이스 정원(1명)이 찼습니다`. 윤지아 (신청 학기 `2026-2`) 가 수강신청 탭에서 데이터베이스(화 3~4)를 신청 → `409` `자료구조 과목과 강의시간이 겹칩니다` (자료구조 화 2~4).

**시연이 끝나면** 서버를 끄고 `git checkout -- data/` 로 샘플 데이터를 되돌립니다. 시연에서 만든 데이터베이스 과목·성적·평가 항목 점수가 모두 사라지고 `git status` 에서 `data/` 변경이 없어집니다.
