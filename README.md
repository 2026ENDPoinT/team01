# team01 — 성적 관리 프로그램

ENDPoinT 해커톤 2026 Team 01 (구현과제 트랙)

C++17 프로그램이 로컬 HTTP 서버로 동작하고, 브라우저에서 `http://localhost:8080` 으로 접속해서 사용합니다.

## 문제 정의

- 대상: 학과 사무실·교수·학생이 같은 성적 데이터를 서로 다른 엑셀·메신저로 따로 관리하는 소규모 학과
- 문제: 성적 입력, GPA(4.5 만점) 계산, 재수강·학사경고 판정, 석차, 수강신청 정원·시간표 겹침 확인이 사람마다 다른 기준으로 수작업되어 오류가 납니다.
- 해결: 하나의 로컬 서버에서 역할(관리자·교수·학생)별 권한으로 입력하고, GPA·석차·학사경고·재수강을 자동 계산해 같은 기준으로 보여 줍니다. 설치 없이 브라우저로 접속하고 데이터는 CSV 파일로 남습니다.
- 시연: 아래 "필수 기능 대응표"(심사 필수 ①~⑤ → 화면 위치·API)와 "시연 시나리오"(클릭 경로와 기대 결과)를 순서대로 따라가면 됩니다.

## 빌드 / 실행

필요: CMake 3.16+, C++17 컴파일러 (GCC, Clang, MSVC, MinGW)

**CLion**: 폴더 열기 → `GradeManager` 실행 → 브라우저에서 http://localhost:8080

**명령줄**
```bash
cmake -B build
cmake --build build
./build/GradeManager          # Windows: build\Debug\GradeManager.exe
./build/GradeManager 9090     # 8080 이 이미 사용 중이면 다른 포트로
```

`data/`, `web/` 경로는 빌드 시 프로젝트 경로로 고정되므로 어디서 실행해도 됩니다.

**테스트**
```bash
cmake -B build && cmake --build build && ctest --test-dir build --output-on-failure
# Windows(Visual Studio): ctest --test-dir build -C Debug --output-on-failure
# CMake 3.20 미만 (--test-dir 없음): cd build && ctest --output-on-failure
```

`tests/` 는 외부 라이브러리 없이 `GradeTests` 하나로 등급 경계·등급 직접 입력 변환, 재수강 규칙, 석차 동점, 평가 항목 최종 점수·성적 자동 계산, 학기별 GPA 요약, 과목코드 변경·삭제 연쇄, CSV 저장/불러오기를 검사합니다 (임시 폴더만 사용, `data/` 는 건드리지 않음).

## 학기 규칙

- 학기 형식: `YYYY-N` (예: `2026-1`), N 은 1~4 — 1·2 는 정규학기, 3 은 여름 계절학기, 4 는 겨울 계절학기 (#20)
- 학생별 허용 학기: 입학년도(2000 + 학번 앞 2자리)-1 ~ (올해+1)-4 (#16). 예: `23101001` 은 2023-1 ~ 2027-4 (2026년 기준). 범위 밖이면 성적·수강신청 등록이 `400`. 이미 저장된 데이터는 다시 검사하지 않습니다.

## 수강신청

- 신청 학기는 관리자가 설정합니다 (`settings.csv`). 비어 있으면 수강신청 기간이 아닙니다. 학생은 신청 학기에만 신청·취소할 수 있고, 관리자는 어느 학기든 대리로 신청·취소할 수 있습니다.
- 신청 검사: 중복 (`409`), 정원 (그 학기 신청 인원이 정원 이상이면 `409`), 같은 학생·학기에 신청한 과목과 강의시간 겹침 (`409`). 강의시간이 빈 과목(원격 등)은 겹치지 않습니다.
- 성적 등록은 같은 (학번, 과목, 학기)의 수강신청이 있어야 합니다 (없으면 `409`). 성적 또는 평가 항목 점수가 있는 수강은 취소할 수 없습니다 (`409`).
- 과목 목록의 수강 표시 (#14): 수강신청이 있는 가장 늦은 학기의 신청 인원 / 학기당 정원 (`GET /api/stats/course/:code` 의 `latestSemester`, `latestEnrolled`)

## 과목 페이지

- 상단 탭 줄에 보이는 과목마다 탭이 하나씩 생깁니다. 보이는 과목은 관리자는 전체, 교수는 담당 과목, 학생은 수강신청한 과목입니다. 수강과목 목록도 같은 과목만 보여 줍니다.
- 과목 페이지는 학기별로 나뉘고, 게시물은 주차(1~16)별로 묶어 보여 줍니다. 분류는 수업자료 `material` · 중간고사 `midterm` · 기말고사 `final` · 과제 `assignment` 4가지입니다.
- 게시물은 제목(필수), 내용, 링크(`http://` 또는 `https://`, 파일 업로드는 없음), 날짜(과제 마감·시험일, `2026-10-20` 또는 `2026-10-20 13:00`)를 가집니다. 작성자와 작성 시각은 서버가 채웁니다.

| 기능 | 관리자 | 교수 | 학생 |
|---|---|---|---|
| 게시물 조회 | 모든 과목 | 담당 과목 | 수강신청한 과목 (그 수강신청 학기의 게시물만) |
| 게시물 추가·수정·삭제 | O | 담당 과목 | X |

## 평가 항목 성적

교수가 과목·학기마다 평가 항목(예: 중간고사·기말고사·과제·출석)과 반영 비율을 정하고 학생별 항목 점수를 넣으면, 최종 점수와 등급이 자동으로 계산되어 `grades.csv` 의 성적이 됩니다. 계산 결과는 평범한 성적이라서 GPA·석차·재수강·학사경고·성적표 코드는 그대로 씁니다 (`include/assessment.h`, `GradeManager` 의 `syncGrade`·`syncCourse`).

- 항목은 (과목코드, 학기, 이름) 으로 구분합니다. 이름은 공백만이면 안 되고 60바이트 이하이며 같은 과목·학기에서 겹칠 수 없습니다. 비율은 정수 1~100 이고 합계는 100 을 넘을 수 없습니다.
- 최종 점수 = Σ(항목 점수 × 비율) ÷ 100, 소수 둘째 자리에서 반올림 (`finalScore`). 예: 비율 중간 30·기말 40·과제 20·출석 10 에 점수 90·80·100·100 → 27 + 32 + 20 + 10 = 89.0 → B+.
- 미완성이면 성적이 없습니다. 비율 합계가 100 이 아니거나 점수가 없는 항목이 하나라도 있으면 그 학생의 성적은 만들어지지 않고, 이미 있던 성적도 지워집니다 (항목 점수를 지우거나 항목을 추가해서 미완성이 된 경우).
- 항목이나 항목 점수를 추가·수정·삭제할 때마다 서버가 성적을 다시 계산합니다. 항목을 바꾸면 그 과목·학기 수강생 전원, 항목 점수를 바꾸면 그 학생만 대상입니다.
  - 항목 이름을 바꾸면 그 항목의 점수도 새 이름으로 따라가고, 항목을 지우면 그 항목의 점수도 지워집니다. 마지막 항목을 지우면 그 과목·학기의 항목 점수와 성적이 모두 지워집니다.
  - 과목코드를 바꾸면 항목·항목 점수의 코드도 바뀌고, 과목이나 학생을 삭제하면 항목·항목 점수도 같이 지워집니다.
- 항목 점수는 0~100 이고, 그 학생의 (과목, 학기) 수강신청이 있어야 입력할 수 있습니다.
- 직접 입력한 성적과 섞이지 않습니다.
  - 그 과목·학기에 직접 입력한 성적이 이미 있으면 첫 항목을 만들 수 없습니다 (`409`).
  - 항목이 하나라도 있는 과목·학기는 성적 직접 등록·수정·삭제가 모두 `409` 입니다.
  - 항목 점수가 있는 수강은 취소할 수 없습니다 (`409`). 수강신청 목록의 `hasGrade` 는 성적 또는 항목 점수가 있으면 `true` 입니다.
- 항목이 없는 과목·학기는 지금처럼 점수 또는 등급(`A+ A0 B+ B0 C+ C0 D+ D0 F` → 95·90·85·80·75·70·65·60·0점으로 저장)으로 직접 입력합니다.
- 예상 성적: 학생의 `내 성적` 화면은 평가 항목이 있는 과목마다 "진행 중 과목 (평가 항목)" 영역에 내 항목 점수와 현재까지 환산을 보입니다. 화면에서 계산하며 저장하지 않습니다.
  - 현재까지 환산 = Σ(입력된 항목 점수 × 비율) ÷ Σ(입력된 항목의 비율). 예상 등급은 `scoreToLetter` 와 같은 경계를 씁니다.
  - 모든 항목이 들어가 최종 성적이 생기기 전에는 "미확정"이고, 생기면 그 성적을 보입니다.
  - 예: 윤지아 `25103008` (중간 72·과제 85·출석 90, 기말 없음) → (72×30 + 85×20 + 90×10) ÷ 60 = 79.33 → C+ (미확정). 기말을 70 으로 입력하면 최종 75.6 → C+ 가 확정됩니다.

| 평가 항목 성적 권한 | 관리자 | 교수 | 학생 |
|---|---|---|---|
| 평가 항목 조회 | O | O | O |
| 평가 항목 추가·수정·삭제 | O | 담당 과목 | X |
| 항목 점수 조회 | 과목·학기 전체 | 담당 과목 | 본인 점수 |
| 항목 점수 입력·수정·삭제 | O | 담당 과목 | X |
| 예상 성적 (`내 성적`) | X | X | 본인 |

학생이 평가 항목·항목 점수를 쓰는 라우트를 부르거나, 교수가 담당이 아닌 과목을 건드리면 `403` 입니다. 과목 페이지의 `평가 항목` 영역(학기 선택, 항목 표, 항목 점수 입력표)은 관리자와 담당 교수에게만 보입니다.

JSON 필드 이름은 헤더의 멤버 이름과 같습니다.
- 학생 `{"id", "name", "major", "year"}`
- 과목 `{"code", "name", "credit", "professor", "category", "area", "schedule", "language", "capacity", "remote"}`
  - `code` 과목코드: 숫자 6자리 (예: `109004`). 수정할 때 바꾸면 그 과목의 성적에 적힌 코드도 같이 바뀜
  - `category` 이수구분: `전공필수` `전공선택` `교양필수` `교양선택` `일반선택`
  - `language` 강의언어: `한국어전용` `영어전용` `모듈강좌(M)`
  - `schedule` 강의시간: `월(1~4)`, `화(2~3) 목(2~3)`, `금(5)` 형식 (빈 값 허용), `area` 교양영역 (빈 값 허용)
  - `capacity` 학기당 정원 (0 = 제한 없음, 최대 999). 정원은 수강신청에서 검사 (그 학기 신청 인원이 정원만큼 있으면 수강신청은 `409`)
  - `remote` 원격강좌 여부 (`true`/`false`)
  - 예전 형식 `courses.csv` (`code,name,credit,professor`) 도 읽고, 다음 저장 때 새 형식으로 바뀜
- 성적 `{"studentId", "courseCode", "semester", "score", "letter"}` — 요청에는 `score` 대신 `letter` 를 보낼 수 있고, 응답의 `letter` 는 서버가 정함 (`scoreToLetter` + 재수강 규칙 `Retake::officialLetter`)
- 수강신청 `{"studentId", "courseCode", "semester", "hasGrade"}` — 같은 (학번, 과목코드, 학기) 하나가 신청 1건
- 게시물 `{"id", "courseCode", "semester", "category", "week", "title", "body", "link", "dueDate", "author", "createdAt"}`
- 계정 `{"username", "role", "name", "studentId"}` — 응답에 비밀번호 해시는 없음. 학생 계정의 `name` 은 학생 이름으로 채워서 내보냄
- 평가 항목 `{"courseCode", "semester", "name", "weight"}` — `weight` 는 반영 비율(%) 정수 1~100
- 항목 점수 `{"studentId", "courseCode", "semester", "name", "score"}` — `score` 는 0~100

데이터를 바꾸는 라우트의 성공 응답은 모두 JSON 입니다. 등록은 `201` + 만든 객체, 수정은 `200` + 바뀐 객체, 삭제는 `200` + `{"deleted": true}` 이고, 성공한 뒤 바로 CSV 에 저장합니다. 성적 응답에는 항상 `letter` 가 들어 있습니다.

## 재수강 규칙

같은 학생이 같은 과목을 여러 학기에 들으면 가장 늦은 학기가 재수강 성적이고, 그 전 성적은 삭제된 성적입니다. 자세한 내용과 함수는 `include/retake.h` 를 참고하세요.

- 재수강 성적은 A0 까지만 받습니다 (95점 이상이어도 A0, 평점 4.0).
- 삭제된 성적은 GPA, 석차, 과목 통계, 과목 성적표에서 빠집니다. `grades.csv` 에는 그대로 남습니다.
- 학생 성적표: 2018년 이후 입학생(학번 앞 2자리 ≥ 18)은 삭제된 과목을 등급 `R` 로 표시하고, 그 전 입학생은 그 줄을 뺍니다.
- 학사경고: 이미 내려진 학사경고는 유지합니다. 학사경고를 판단할 때는 재수강 규칙을 적용하지 않고 원래 성적(`scoreToLetter`)을 씁니다 (`statistics.h` 의 `academicWarnings`).
  - 기준: 정규학기 평점평균 1.75 미만, 또는 수강신청 미이행 (그 학기에 신청한 학점이 1 미만)
  - 판단 학기: 그 학생이 처음 수강신청한 학기부터, 전체 성적 데이터에 있는 가장 늦은 정규학기(N=1·2)까지 정규학기마다 봅니다. 계절학기는 판단하지 않습니다. 수강신청 기록이 없는 학생은 판단하지 않고, 휴학 데이터가 없으므로 모두 재학생으로 봅니다.
  - 각 학기: 신청 학점 합계가 1 미만이면 `수강신청 미이행`, 아니고 그 학기 성적이 1건 이상이면 학점 가중 평점(재수강으로 지워진 성적도 포함)이 1.75 미만일 때 `평점평균 1.75 미만`
  - 결과 항목 `{semester, reason, gpa, credits}` (`gpa` 가 없으면 `null`, `credits` = 그 학기 신청 학점). 샘플 데이터에서는 최유진 2025-2·2026-1, 강도윤 2026-1, 윤지아 2025-2, 한지민 2025-1 (평점)·2026-1 (수강신청 미이행)

## 필수 기능 대응표

심사 기준(`docs/judging-criteria.md`)의 필수 ①~⑤와 완료 기준 6개가 어느 화면·API 인지 정리한 표입니다. 화면 위치는 관리자 계정(`admin` / `admin1234`) 기준이고, 교수는 담당 과목만 같은 화면을 씁니다.

| 필수 기능 | 화면 위치 | API |
|---|---|---|
| ① 과목·성적 등록 (과목명, 수강 학기, 학점, 성적 등급) | 수강과목 탭 `+ 과목 등록` (과목명·학점) → 수강신청 탭 (학생·과목·학기 선택 후 `신청`) → 성적 탭 `+ 성적 등록` 에서 입력 방식 `등급` 선택 (A+ ~ F) | `POST /api/courses`, `POST /api/enrollments`, `POST /api/grades` (`letter`) |
| ② 과목 조회·관리 (학기별 구분, 수정·삭제) | 성적 탭 목록 (학기·학생·과목으로 거르기, 행마다 `수정` `삭제`), 수강과목 탭·과목 탭의 과목 목록·정보 (`수정` `삭제`) | `GET /api/grades?semester=`, `PUT`·`DELETE /api/grades`, `PUT`·`DELETE /api/courses/:code` |
| ③ 평점평균(GPA) 자동 계산 (4.5 만점, 소수 둘째 자리) | 학생 탭 → `성적표` 대화상자: 누적 GPA·등록 학점, 학기별 평점평균·등록 학점 표, GPA 변화 그래프. 학생 계정은 `내 성적` 탭 (같은 화면). 석차 탭의 GPA 도 같은 값 | `GET /api/stats/summary/:id`, `GET /api/stats/gpa/:id`, `GET /api/stats/ranking` |
| ④ 데이터 저장·불러오기 | 모든 등록·수정·삭제가 바로 `data/*.csv` 에 저장됨. 새로고침하거나 서버를 다시 켜고 로그인해도 같은 값 | 데이터를 바꾸는 라우트가 성공 뒤 `gm.save()` |
| ⑤ 기본 예외 처리 | 과목명 빈칸, 학점 0·숫자 아님, 지원하지 않는 등급, 성적 없는 학생 GPA 는 서버가 `400` + 메시지(GPA 는 `null`)로 돌려주고 화면이 오류 문구를 알림으로 보임. 성적 없는 학생(조서준)의 성적표는 "등록된 성적이 없습니다" | `400` 응답 (아래 시연 시나리오의 6번에 실제 문구), `GET /api/stats/gpa/:id` 의 `"gpa": null` |

| 완료 기준 | 확인 위치 |
|---|---|
| 학기 구분: 서로 다른 학기의 과목을 등록할 수 있다 | 성적 탭 `+ 성적 등록` 에서 학기를 2026-1·2026-2 로 따로 등록 → 성적 탭 학기 선택으로 구분 |
| 추가 반영: 추가하면 목록과 GPA 에 반영된다 | 성적 등록 직후 성적 탭 목록, 학생 탭 `성적표` 의 학기별·누적 GPA |
| 수정 반영: 성적이나 학점을 고치면 GPA 가 다시 계산된다 | 성적 탭 `수정` 후 `성적표`. 평가 항목 점수를 고쳐도 같음 (과목 페이지의 항목 점수 입력표) |
| 삭제 반영: 삭제하면 목록과 GPA 에 반영된다 | 성적 탭 `삭제` 후 목록과 `성적표` |
| 데이터 유지: 새로고침·재실행해도 유지된다 | F5, 서버 재시작 후 같은 성적표 |
| 예외 처리: 잘못된 값을 입력해도 비정상 종료 없이 처리한다 | 시나리오 6번 (모든 경우 서버 계속 동작) |

## 시연 시나리오

서버를 `./build/GradeManager` 로 띄우고 http://localhost:8080 에서 따라갑니다. 숫자는 샘플 데이터 기준이고, GPA 는 화면에 소수 둘째 자리까지 나옵니다. 앞부분은 심사 필수 기능 순서(1~6), 뒤는 차별점(7~11)입니다.

**필수 기능 (관리자 `admin` / `admin1234`)**

1. 학기 구분, 과목·성적 등록 (필수 ①)
   1. 수강과목 탭 `+ 과목 등록`: 과목 코드 `109501`, 과목명 `데이터베이스`, 이수구분 전공선택, 학점 3, 담당 교수 `이영희`, 강의시간 `화(3~4)`, 정원 `1` → 저장. 기대: 상단에 `데이터베이스` 탭이 생김.
   2. 수강신청 탭: 학생 김민준, 과목 데이터베이스, 학기 `2026-1` → `신청`.
   3. 성적 탭 `+ 성적 등록`: 김민준, 데이터베이스, 학기 `2026-1`, 입력 방식 `등급` → `A+` → 저장. 기대: 목록에 2026-1 데이터베이스 95점 A+ (등급 대표 점수).
   4. 다른 학기: 수강신청 탭에서 김민준·캡스톤디자인·학기 `2026-2` 신청 → 성적 탭 `+ 성적 등록`, 입력 방식 `점수` 에 `87` → 저장. 기대: B+. 성적 탭 학기 선택으로 2026-1 과 2026-2 가 따로 보임.
2. 추가 반영: 학생 탭에서 김민준 `성적표`. 기대: 학기별 표 2025-1 3.94 / 8학점, 2025-2 4.50 / 3학점, 2026-1 4.00 / 6학점, 2026-2 3.50 / 4학점, 누적 3.95 / 21학점 (추가 전 누적은 3.96 / 14학점). 학기별 GPA 변화 그래프도 4점으로 그려짐.
3. 수정 반영: 성적 탭에서 김민준 캡스톤디자인 2026-2 `수정` → 점수 `92` (A0). 기대: `성적표` 의 2026-2 가 4.00, 누적 4.05. 석차 탭에서 김민준 2위 (4.05, 1위 정하은 4.18).
4. 삭제 반영: 같은 성적을 `삭제`. 기대: 성적표에서 2026-2 줄이 사라지고 누적 4.06 / 17학점.
5. 데이터 유지: 브라우저를 새로고침(F5)해도 같음. 터미널에서 Ctrl+C 로 서버를 끄고 다시 실행해 로그인하면 김민준 성적표가 그대로 (데이터베이스 2026-1 A+, 누적 4.06 / 17학점). `git diff data/` 에도 변경이 보임.
6. 예외 처리 (필수 ⑤). 서버는 모든 경우에 계속 동작합니다.
   - 수강과목 탭 `+ 과목 등록` 에서 과목명을 비움: `400` `과목 정보가 올바르지 않습니다 (과목명이 비어 있습니다)`
   - 학점 `0`: `400` `과목 정보가 올바르지 않습니다 (학점은 1~4 사이여야 합니다)`
   - 학점 `abc` (화면 숫자 칸으로는 못 넣으므로 curl): `400` `과목 정보가 올바르지 않습니다`
   - 성적 등급 `A` (화면 선택 상자에는 없는 값이라 curl): `400` `지원하지 않는 성적 등급입니다 (A+ A0 B+ B0 C+ C0 D+ D0 F)`
   - 성적 없는 학생: 학생 탭에서 조서준 `성적표` → "등록된 성적이 없습니다" (`GET /api/stats/gpa/26101007` → `{"gpa":null}`)

   curl 예 (`admin` 로그인 쿠키를 `jar` 에 저장):
   ```bash
   curl -s -c jar -H 'Content-Type: application/json' -d '{"username":"admin","password":"admin1234"}' localhost:8080/api/login
   curl -s -b jar -H 'Content-Type: application/json' -d '{"code":"109502","name":"운영체제","credit":"abc","professor":"이영희"}' localhost:8080/api/courses
   curl -s -b jar -H 'Content-Type: application/json' -d '{"studentId":"23101001","courseCode":"109501","semester":"2026-1","letter":"A"}' localhost:8080/api/grades
   curl -s -b jar localhost:8080/api/stats/gpa/26101007
   ```

**차별점**

7. 평가 항목 자동 계산과 예상 성적: 교수 `leeyh` / `prof1234` 로 로그인 (로그아웃 후).
   1. 상단 `자료구조` 탭 → 학기 `2026-2` 선택 → `평가 항목` 영역. 기대: 중간고사 30·기말고사 40·과제 20·출석 10, `비율 합계 100 / 100`.
   2. 항목 점수 입력표에서 강도윤 행은 중간 90·과제 100·출석 100 이고 기말이 비어 있어 최종 `-`. 기말에 `80` 입력. 기대: 최종 89.0 B+, 성적 탭에 자료구조 2026-2 강도윤 B+ 가 자동으로 생김.
   3. 수정 반영(항목 점수): 기말을 `100` 으로 고침 → 97.0 A+, 다시 `80` → 89.0 B+. 기말 칸을 비우면 최종이 `-` 로 돌아가고 성적이 사라짐 (다시 `80` 입력). 관리자의 강도윤 성적표에서 2026-2 는 3.50 / 3학점, 누적 2.31 → 2.64 (11학점).
   4. 비율 합계 보호: 항목 `퀴즈` 5% 추가. 기대: `409` `비율 합계가 100을 넘습니다 (지금 100%)`.
   5. 직접 입력 차단: 자료구조 2026-2 에 성적을 직접 등록·수정·삭제하면 `409` `평가 항목으로 성적을 계산하는 과목입니다 (평가 항목 화면에서 점수를 입력하세요)`. 항목 점수가 있는 수강은 수강신청 탭의 `취소` 버튼이 비활성화되고, API 로 취소하면 `409` `성적이 있는 수강은 취소할 수 없습니다`.
   6. 학생 `25103008` / `student1234` (윤지아) 로그인 → `내 성적` 탭의 "진행 중 과목 (평가 항목)": 자료구조 2026-2 현재까지 환산 79.33 (C+, 미확정). 교수가 윤지아 기말에 `70` 을 입력하면 최종 75.6 C+ 가 확정되고, 내 성적의 2026-2 가 2.50 / 3학점, 누적 2.00 / 9학점이 됨.
8. 재수강 `R` / A0 제한: 관리자 학생 탭에서 윤지아 `성적표` → 미적분학 2025-2 줄이 등급 `R`(삭제된 성적), 2026-1 재수강 성적이 반영됨. 한지민 `성적표` → 자료구조 2025-2 는 97점이어도 A0 (재수강은 A0 까지), 2025-1 줄은 빠짐 (2017년 입학).
9. 학사경고: 학생 탭의 학사경고 열과 각 `성적표` 의 학사경고 목록. 기대: 최유진 2025-2·2026-1, 강도윤 2026-1, 윤지아 2025-2, 한지민 2025-1 (평점)·2026-1 (수강신청 미이행). 석차 탭에서는 이서연·박지호가 같은 등수.
10. 역할별 권한: 윤지아로 로그인한 상태에서는 수강과목·수강신청·내 성적 탭만 보이고, 남의 GPA (`GET /api/stats/gpa/23101001`) 는 `403` `권한이 없습니다`. 교수 `kimcs` / `prof1234` 는 담당 과목 109001 만 다루고, 109201 의 평가 항목 점수 조회·평가 항목 추가는 `403` `권한이 없습니다`.
11. 수강신청 정원·시간 충돌: 관리자가 이서연으로 데이터베이스 `2026-1` 신청 → `409` `2026-1 데이터베이스 정원(1명)이 찼습니다`. 윤지아 (신청 학기 `2026-2`) 가 수강신청 탭에서 데이터베이스(화 3~4)를 신청 → `409` `자료구조 과목과 강의시간이 겹칩니다` (자료구조 화 2~4).

**시연이 끝나면** 서버를 끄고 `git checkout -- data/` 로 샘플 데이터를 되돌립니다. 시연에서 만든 데이터베이스 과목·성적·평가 항목 점수가 모두 사라지고 `git status` 에서 `data/` 변경이 없어집니다.
